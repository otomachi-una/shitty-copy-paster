## Distribution Mode

The proven mode is source delivery. Builds use committed vendored dependencies
with `GOFLAGS=-mod=vendor`; the proof does not fetch Go modules from the
network. Docker is used to start PostgreSQL for live runtime smoke and to
validate the candidate Compose template. Image build/push is not the acceptance
mechanism for this wave.

The competition runtime profile is now selected explicitly by neutral build
tags. The canonical source build command is `make competition-runtime-build`,
which compiles `./cmd/aml-api`, `./cmd/aml-worker`, and `./scripts/migrate`
with:

```sh
-tags "case_match_preview audit_detail_view entity_review_summary linked_case_export_detail network_room_detail"
```

The staged player candidate Dockerfile generated by
`scripts/build_player_bundle.py` uses the same tag set as its default
`COMPETITION_TAGS` build argument for `aml-api`, `aml-worker`, and
`aml-migrate`. This closes the default-secure Dockerfile risk for the staged
source candidate while still leaving secure/default source variants in the
organizer repository. This proof still does not issue a final player package,
archive, manifest, checksum, or promoted image.
